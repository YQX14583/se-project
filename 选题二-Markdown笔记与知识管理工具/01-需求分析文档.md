## 1. 项目背景

### 1.1 问题陈述

知识工作者和学生日常积累的笔记分散在多个工具（备忘录、Word、聊天记录收藏、纸质笔记）中，存在四个痛点：

1. **格式割裂**：不同工具的笔记互不兼容，迁移成本高，一旦工具停止服务数据即被锁定。
2. **检索低效**：笔记数量超过数百条后，仅靠文件夹分类难以快速定位，"记得写过但找不到"是高频场景。
3. **知识孤岛**：笔记之间缺乏关联（链接、标签），无法形成可生长的知识网络，笔记写完即被遗忘。
4. **多端不一致**：在电脑上写、在手机上读的需求普遍，但现有方案或需付费、或同步不稳定。

Markdown 作为纯文本、人类可读、生态成熟的轻量标记语言，已成为技术社区事实上的笔记格式标准。基于本地 Markdown 文件构建笔记工具，可以让用户**拥有数据主权**（文件永远可用任何编辑器打开），同时通过软件提供结构化管理能力。

### 1.2 产品定位

MarkHub 是一款**以本地 Markdown 文件为存储底座的个人笔记与知识管理工具**：

- 笔记即文件：所有内容存储为用户可自由访问的 `.md` 文件，不锁定数据；
- 管理即服务：软件提供编辑、检索、标签、双向链接、知识图谱等增值能力；
- 个人优先：面向单用户本地使用（v1.x），多端同步作为云增值能力（v2.x）。

### 1.3 目标用户与典型场景

| 用户画像 | 特征 | 核心诉求 |
|---|---|---|
| 在校学生（主要） | 课程笔记、复习资料多，预算有限 | 免费、快速记录、考前高效检索 |
| 程序员/技术写作者 | 熟悉 Markdown，笔记与代码混杂 | 代码块高亮、Git 管理、双链 |
| 研究人员 | 文献笔记、引文多 | 标签体系、全文检索、引用链接 |

**场景 1（速记→整理）**：上课时学生用手机快速记下要点（每条自动成为独立小笔记），晚上在电脑上打开"今日速记"收件箱，将内容合并、拆分并归档到课程笔记中。
**场景 2（检索复习）**：考试前学生搜索"特征值"，系统毫秒级返回所有包含该词的笔记及上下文高亮片段，并可按课程标签过滤。
**场景 3（知识关联）**：写"快速排序"笔记时键入 `[[`，系统即时提示已有笔记名，选择后建立双向链接；之后在"排序算法总览"中自动看到反向引用了"快速排序"。
**场景 4（无损迁移）**：用户决定试用竞品，直接把笔记文件夹拷走——所有笔记都是标准 `.md` 文件，图片等附件在 `assets/` 子目录中相对引用，不丢失、不失真。

## 2. 系统范围

### 2.1 范围内（In Scope）

- 单机（Windows / macOS / Linux 桌面端）笔记管理客户端；
- 基于用户自选本地文件夹（Vault）的读取、监控与写入；
- Markdown 编辑（含实时预览）、组织（文件夹/标签/收藏）、检索、双向链接与关系图、附件管理、回收站、导出。

### 2.2 范围外（Out of Scope，v1.x 不承诺）

- 多人协同编辑（实时冲突合并算法，规划 v3.0 课题）；
- 移动端原生 App（v2.x 提供响应式 Web 视图作为过渡）；
- 富文本/WYSIWYG 所见即所得深度编辑（v1.x 为分栏实时预览）；
- AI 摘要/问答等智能功能（数据合规评估完成前不引入）。

### 2.3 假设与依赖

- A1：用户具备基础 Markdown 语法知识（产品提供速查卡降低门槛）。
- A2：操作系统提供文件变更通知机制（inotify/FSEvents/ReadDirectoryChangesW），轮询作为降级方案。
- A3：单 Vault 笔记规模假设 ≤ 50,000 篇、单篇 ≤ 2 MB、总量 ≤ 2 GB；超出此规模性能指标不承诺（见 NFR-01 边界）。

## 3. 功能需求

优先级采用 MoSCoW 法：**Must**（v1.0 必须）、**Should**（v1.1 应当）、**Could**（v2.0 可以）。每条需求给出唯一 ID、可验证的验收标准（Given/When/Then 或等价量化表述）。缩写约定：G=Given（前置），W=When（操作），T=Then（预期）。

### 3.1 笔记编辑（Must）

**FR-01 创建笔记**
用户可在当前文件夹任意位置创建新笔记。
验收标准：
- G 已打开某 Vault；W 用户点击"新建笔记"；T 在当前目录生成 `未命名.md`（重名时自动追加 `-1`、`-2`），编辑器打开该文件且光标位于空正文首行。
- 输入标题后按回车或失焦，文件重命名为标题内容（非法文件名字符自动替换为 `-`）。
- 边界：标题含 `/ \ : * ? " < > |` 或为空时，不弹系统错误，按规则净化后保存；净化后为空则保留 `未命名`。

**FR-02 Markdown 编辑器**
提供纯文本编辑区，支持常用 Markdown 语法输入。
验收标准：
- 支持的语法范围：标题(#)、粗体、斜体、行内代码、代码块(```)、引用(>)、有序/无序列表、任务列表(- [ ])、表格、链接、图片、水平分割线。以项目 `syntax-support.md` 清单为准，清单外语法不承诺渲染。
- 快捷键：Ctrl/Cmd+B 加粗、Ctrl/Cmd+I 斜体、Ctrl/Cmd+K 链接，对选中文本生效；未选中时插入语法骨架并定位光标。
- 边界：单个代码块超过 10,000 行时编辑器仍可输入，但语法高亮降级为纯色（允许，需在状态栏提示"大文件高亮已降级"）。

**FR-03 实时预览**
编辑区分栏时，右侧渲染区随输入更新 HTML 渲染结果。
验收标准：
- G 编辑区开启分栏；W 用户输入合法 Markdown；T 预览在 **300 ms 内**（P95，输入停止后计）完成更新。
- 预览渲染结果与 CommonMark 0.31 规范一致（以规范测试集通过率 ≥ 99% 度量）；GFM 扩展（表格、任务列表、删除线）同样支持。
- 边界：包含未闭合代码块等非法结构时，按 CommonMark 规则容错渲染，应用不得崩溃或白屏。

**FR-04 保存与自动保存**
- 手动保存：Ctrl/Cmd+S 立即写盘，状态栏显示"已保存 HH:MM:SS"。
- 自动保存：停止输入 **2 秒**后自动写盘；应用退出（含系统强杀前的正常关闭流程）时若有未保存内容，强制写盘。
- 边界：写盘失败（如文件被外部程序独占锁定）时，状态栏红条提示，编辑内容保留在内存缓冲区不丢失，并每 10 秒重试。

### 3.2 组织与导航（Must）

**FR-05 文件树**
左侧以树形展示 Vault 内全部 `.md` 文件与文件夹。
- 支持展开/折叠、新建/重命名/删除文件夹；
- 外部程序修改文件时 **≤ 2 秒**内反映到树上（文件监听）；
- 边界：监听不可用时降级为 10 秒轮询 + 手动刷新按钮（状态栏标明"监听已降级"）。

**FR-06 标签系统**
- 笔记内 YAML front matter 中 `tags: [a, b]` 或正文行内 `#tag` 均可产生标签；
- 左侧标签面板按字母序列出全部标签及计数，点击标签过滤笔记列表；
- 支持多标签交集过滤（点击第二个标签时默认取交集，UI 上可切换并集）。

**FR-07 收藏/置顶**
用户可将任意笔记标记收藏；收藏列表独立展示于侧栏顶部，按收藏时间倒序，数量上限 100 条（超出时提示移除最早项）。

**FR-08 全文检索**
- 输入关键词，**≤ 500 ms**（P95，1 万篇笔记库）返回结果，按相关度排序；
- 结果条目显示：笔记标题、命中片段（关键词高亮、上下文各 ~40 字符）；
- 支持语法：多词空格（AND）、`"精确短语"`、`tag:xxx` 过滤、`path:xxx` 目录内限定；
- 边界：0 结果时展示友好空态及搜索语法帮助入口，而非空白。

### 3.3 知识关联（Must：双链；Should：关系图）

**FR-09 双向链接（ wiki-link ）**
- 编辑器中输入 `[[` 触发笔记名自动补全（模糊匹配标题，≤ 50 ms 出候选）；
- 渲染为可点击链接；目标笔记不存在时渲染为"虚链"（灰色带 + 号），点击即创建该笔记；
- 被链接的笔记底部自动出现"反向链接"区块，列出所有引用本笔记的笔记及所在段落摘要。

**FR-10 关系图（Should）**
以节点-边形式可视化全部双链关系：节点=笔记（大小按出度+入度），边=链接；支持拖拽、缩放、悬停高亮邻居；节点数 > 2,000 时提供过滤（按标签/文件夹裁剪），保证帧率 ≥ 24 FPS。

### 3.4 附件与导入导出（Must：导出；Should：附件拖入）

**FR-11 附件管理（Should）**
拖拽图片到编辑器，自动复制到笔记同目录 `assets/` 下（重名追加序号），并插入相对路径引用 `![](assets/xxx.png)`；单附件 ≤ 25 MB，超限提示。

**FR-12 导出（Must）**
单篇/多选/整个文件夹导出为：HTML（内嵌或同目录图片）、PDF、纯 Markdown 打包（`.zip`，含相对结构）。PDF 分页不切断代码块（若单块超一页则允许切断并标注续）。

**FR-13 导入（Should）**
批量导入 `.docx`（转换标题/列表/粗斜体）、`.html`、`.txt` 为 Markdown；转换不支持的元素降级为纯文本并在日志中逐条记录，不允许静默丢弃内容。

### 3.5 安全与数据保护（Must）

**FR-14 回收站**
删除笔记/文件夹时移入 Vault 内 `.trash/` 隐藏目录（不直接删除）；回收站面板可恢复（回到原路径，路径已不存在则恢复到根目录）或彻底删除（二次确认）。`.trash/` 内文件不参与搜索与关系图。

**FR-15 历史版本（Should）**
每次自动保存生成版本快照，按笔记保留最近 **50** 个或 **90 天**内版本（先到者为准，滚动清理）；可对比任意两版本差异（ unified diff 视图）并回滚。

**FR-16 本地锁定**
可选为 Vault 设置本地口令锁（打开应用需解锁）；口令经 PBKDF2（≥ 100,000 次迭代）派生密钥加密存储配置文件，不加密笔记正文（正文加密属 v2.0 范围）。

### 3.6 辅助能力

**FR-17 速记收件箱（Could）** 系统级全局快捷键唤起速记小窗，保存后写入 `Inbox/`；参看场景 1。
**FR-18 模板（Should）** 新建笔记可选模板（会议记录、读书笔记等），模板存放于 `.templates/`，支持用户自定义。
**FR-19 主题（Could）** 亮/暗主题及字体大小调节，跟随系统切换。
**FR-20 多语言界面（Could）** 中/英界面，跟随系统语言，可手动切换。
**FR-21 键盘可达性（Should）** 全部功能可通过键盘菜单/命令面板（Ctrl/Cmd+P）触达，无鼠标依赖。
**FR-22 统计面板（Could）** 展示笔记数、字数、近 30 天写作热力图。

| NFR-08 | 可用性 | 新用户无文档完成"新建→书写→搜索"三步任务成功率 ≥ 90%（10 人可用性测试，SUS 问卷 ≥ 75 分） | 可用性实验报告 |
| NFR-09 | 无障碍 | 界面控件可被屏幕阅读器识别（ARIA 标注覆盖 100% 交互控件）；全键盘操作；对比度 ≥ WCAG 2.1 AA | axe 自动扫描 + 人工屏幕阅读器抽查 |

| NFR-11 | 国际化 | 界面文案全部外置 i18n 资源文件；日期/数字按 locale 格式化 | i18n 完整性脚本检查（无硬编码文案） |

## 5. 数据与接口约束（补充规格）

1. **Vault 布局**：`notes/**/*.md`（笔记）、`assets/**`（附件）、`.trash/`、`.templates/`、`.markhub.json`（工作区配置）。隐藏目录（`.`开头）一律不索引。
2. **索引数据库**：`/.markhub/index.db`（SQLite），仅作加速缓存；删除后可全量重建且与文件系统最终一致（重建 1 万篇 ≤ 60 s）。
3. **front matter 规范**：YAML，仅支持标量与字符串数组字段（title/tags/date），非法 YAML 时告警并按无 front matter 处理，不崩溃。

## 6. 边界条件与异常场景汇总

| 场景 | 约定行为 |
|---|---|
| Vault 被外部程序整目录删除/移动 | 检测到根失效 → 弹窗指引重新选择路径；缓冲区内容转存临时恢复文件 |
| 同一笔记被外部编辑器同时修改 | 保存前比对 mtime，不一致时弹"文件已在外部改变"三选一：覆盖 / 重载 / 另存副本 |
| 文件名跨平台非法字符 / 超长（>255 字节） | 创建/重命名时净化并提示（见 FR-01） |
| 磁盘写满 | 写盘失败按 FR-04 重试路径处理，绝不静默丢内容 |
| 环形双链（A→B→A） | 渲染与关系图均不递归展开，关系图去重为单边 |
| 检索包含正则特殊字符的查询串 | 一律按字面量处理，特殊字符不解释 |
| 超大单文件（> 2 MB） | 打开时提示并关闭实时预览，仅纯文本编辑（性能保护） |
| 零笔记 / 首次启动 | 引导创建或打开 Vault 的空态向导 |

## 7. 验收标准（Release 级）

v1.0 发布需同时满足：

1. 全部 Must 级需求（FR-01~09、12、14；NFR-01~07、09、12）逐条通过需求级验收用例，用例与需求 ID 双向追溯（见追溯矩阵）；
2. 三平台 E2E 冒烟套件（创建→编辑→双链→搜索→导出→删除恢复）全绿；
3. 无 P0/P1 级未修复缺陷；P2 缺陷 ≤ 5 个且均有规避说明；
4. 可用性测试（NFR-08）达标并附实验报告。

| 需求 ID | 验收用例 ID | 用例名称 | 类型 |
|---|---|---|---|
| FR-01 | TC-FR01-01 | 新建笔记命名与重名处理 | 功能 |

## 8. 术语表
