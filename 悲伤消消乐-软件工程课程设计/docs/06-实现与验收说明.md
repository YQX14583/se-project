## 2. 本地数据存放在哪

### 2.1 存储介质

纯前端单机游戏，没有服务器和数据库，也不会把进度写进项目文件夹。数据存在浏览器的 **`localStorage`**，按站点（origin）隔离：

- 当前站点：`http://127.0.0.1:8770`
- 换端口或换域名会变成另一个 origin，读不到原来的进度；
- 换浏览器、换设备也不互通。

### 2.2 键名

| 键名 | 内容 |
| --- | --- |
| `sadmatch.profile.v1` | 关卡进度、星级、总分、道具库存、设置、日记状态 |
| `sadmatch.run.v1` | 当前未完成一局的断点快照（盘面、悲伤值、剩余步数、分数、阴云） |
| `sadmatch.corrupt.v1` | 无法解析的坏档备份（只保留一份） |
| `sadmatch.diag.v1` | 预留的原型诊断键；正式版不写入 |

### 2.3 查看方式

- 游戏内：设置 →「本地数据存放在哪里」，会显示当前 origin 与键名；
- Chrome / Edge：DevTools → Application → Storage → Local Storage → `http://127.0.0.1:8770`；
- Safari：Develop → Web Inspector → Storage → Local Storage；
- Firefox：DevTools → Storage → Local Storage；
- Console：`localStorage.getItem('sadmatch.profile.v1')`。

### 2.4 macOS 上的实际文件

Chrome / Edge 的 Local Storage 在浏览器配置目录中，通常是：

```text
~/Library/Application Support/Google/Chrome/Default/Local Storage/leveldb/
~/Library/Application Support/Microsoft Edge/Default/Local Storage/leveldb/
```

Safari 在 `~/Library/Safari/` 或 Safari 容器下的网站数据目录；Firefox 在：

```text
~/Library/Application Support/Firefox/Profiles/<profile>/storage/default/http+++127.0.0.1+8770/ls/
```

Chromium 系的 `leveldb` 是二进制格式，不建议手改；用 DevTools 查看/删除最稳妥。

### 2.5 什么时候会丢

- 设置 →「清除全部进度」：重置档案（写回空档案）；
- 浏览器「清除站点数据」：连同 `localStorage` 一起删除；
- 无痕/隐私模式或浏览器拒绝存储：自动降级为内存存档，关闭页面即丢失，界面会提示；
- 换端口、换浏览器、换设备：数据不互通。

## 3. 运行方式

### 3.1 Windows

把整个项目文件夹复制到 Windows 后，双击根目录的 `start-windows.bat`；脚本会优先用 Node.js、其次用 Python 3 启动本地静态服务器，并打开 <http://127.0.0.1:8770>。

也可以手动在项目根目录执行：

```powershell
node scripts/serve.mjs
# 或
py -3 -m http.server 8770 --bind 127.0.0.1 --directory app
# 或
python -m http.server 8770 --bind 127.0.0.1 --directory app
```

### 3.2 macOS / Linux

```bash
cd 悲伤消消乐-软件工程课程设计
python3 -m http.server 8770 --bind 127.0.0.1 --directory app
# 或 node scripts/serve.mjs / npm start
```

浏览器打开 <http://127.0.0.1:8770>。

无构建步骤、无 npm 运行时依赖、无 CDN、无后端。不要直接双击 `app/index.html`，`file://` 下 ES Module 会被浏览器拦截。

## 5. 关键实现口径

### 5.1 情绪层：调和 S0 与步数预算

需求同时规定：

- FR-LV-01：每关开局 S0 = 40–100；
- FR-LV-09：单关 40–90 步；
- FR-LV-01 的减免公式：`floor(消除方块数 × (1 + 0.2 × (连锁数 - 1)))`。

按该公式，40–100 点悲伤值通常在 9–24 步内清空（第 6 节模拟可以复现），无法填满 40–90 步。展示版采用**情绪层**调和：

- 每关 2 层，每层 S0 仍在 40–100；
- 层间不重置步数、分数、道具次数、阴云；
- 当前层归零后，悲伤值回涨到下一层 S0，并显示“情绪又涌上来一点”；
- 全部层归零才算 T1 达标。

公式本身没有改动。该设计是对“S0≤100 + 40–90 步”两个约束的实现级取舍，属于需求内部数值张力的处理，不改变任何需求编号。

### 5.2 T1 与追加目标

- 三关都只有 T1，清零即通关。
- T2–T5（共鸣收集 / 清散阴云 / 连锁挑战 / 精准放晴）的判定函数保留在 `rules.js`，但展示版没有关卡使用，也没有入口；不把它们算作本次交付内容。
- 如果以后开放更多关卡，`evaluateGoals` 已能返回对应进度。

### 5.3 数值

- 悲伤减免：`max(1, floor(count × (1 + 0.2 × (chain - 1))))`，与 FR-LV-01 一致。
- 共鸣值：`10 × count × (1 + 0.5 × (chain - 1))`；阴云消散 +50；通关 +20 × 剩余步数。
- 星级：1 星达标；剩余 ≥25% 升 2 星；剩余 ≥45% 且阴云为 0 升 3 星；温柔模式截断到 2 星。
- 总分：各已通关关卡历史最高分之和；重玩只刷新最高分，不累加。
- 道具：库存上限 5，单关最多 2 次；道具消除走同一结算函数，完整计分、完整减悲伤值。

### 5.4 阴云

三关都在教学段，`cloudEnabled = false`，不会生成阴云。阴云逻辑仍在 `BoardEngine` 中：`S/S0 > 50%` 时每 3 步生成 1 朵、场上最多 3 朵、相邻消除命中 3 次消散、不扣步。它属于设计基线的一部分，但本次展示版不展示。

### 5.5 存档

- `localStorage` 单键写入：`sadmatch.profile.v1` 与 `sadmatch.run.v1`；
- 每次稳定结算、切后台、`pagehide`、每 5 秒计时保存一次；
- 载入时做 schema、外键、数组上限、枚举、棋盘快照校验；
- 解析失败：原始值备份到 `sadmatch.corrupt.v1`，从新档案开始，不读取半截状态；
- `localStorage` 不可用：内存降级，界面明确提示“本次进度只保存在内存”；
- 已完成/失败的局会清除断点，避免恢复一个已结算的盘面。

### 5.6 分享

- 1080×1920 Canvas 离屏绘制：章节/关卡、星级、共鸣值、悲伤清零、情绪文案、游戏名；
- 每章 8 条情绪向文案，按 `runId` 稳定抽取；不含竞争/炫耀话术；
- 保存图片、复制文案、系统分享（能力检测）；系统分享不可用时自动回退到保存 + 复制；
- 不绑定任何道具/分数/进度奖励；
- 不含账号、设备、位置或第三方标识，不上传数据。

### 5.7 计时与温柔模式

- 单局 6 分钟硬上限：计时到 360 秒时，若已清零则通关，否则按超时失败结算；
- 切后台/打开暂停/分享弹层时暂停计时，回来继续；
- 同一关连续失败 3 次后，下一次 `moveBudget + 10`、`starCap = 2`；通关后重置连败计数。

### 5.8 展示版 gating

- `PLAYABLE_LEVEL_IDS = ['C1-L01', 'C1-L02', 'C1-L03']`；
- 地图渲染全部 5 章 × 15 关；只有 3 个节点 `isUnlocked = true`，其余显示为未解锁；
- 未解锁节点仍可见，但点击只提示“尚未解锁”；即使通过接口调用 `startLevel` 也返回 `LEVEL_LOCKED`；
- 测试/模拟通过 `allowAllLevels` 打开全部 75 关，仅用于规则回归与难度采样。

### 5.9 演出与动画

- 消除帧按连锁等级显示 `CHAIN ×N`，2 连锁“不错”、3 连锁“连锁”、4 连锁“心动连锁”、5+“疗愈爆发”；
- 消除格生成彩色粒子、扩散光环和飘分，3 连锁以上触发轻震屏；
- 音效随连锁提高音高，3 连锁以上叠加 combo 提示音；
- 通关先播放太阳光芒 + “放晴了”演出，再打开结算；
- 结算页有旋转光芒、彩纸、`PERFECT/CLEAR` 印章、星星逐颗亮起、共鸣值数字滚动、最高连锁展示；
- 动画是叠加层，不改变结算事务；仍遵守单步 ≤0.6s、整链 ≤2s 的预算。

## 7. 已知偏差与限制

### 7.1 范围

- **3 关展示版**：只解锁第 1 章前 3 关；第 1 章 L04–L15 与其他 4 章仍显示为未解锁节点，暂不可进入。
- **章节解锁**：代码保留通过上一章第 15 关解锁下一章的逻辑，但展示版没有可到达的后续章节。
- **排行榜/账号/联网**：按 FR-LB-01 仍不做；无服务端、无第三方 SDK。
- **日记**：代码保留章节日记数据与页面函数，但展示版没有章末关入口，不作为交付内容。

### 7.2 引擎

- **Cocos Creator 3.8.8 → 原生 HTML5/ES Modules**：当前环境没有 Cocos 编辑器，无法构建/验证 Cocos 产物；展示版用零依赖静态实现，领域层与 Cocos 解耦，便于后续迁移。这是 C-07 / NFR-12 的已知偏差。
- **音效/动画**：音效为 WebAudio 合成，不是音频素材；动画用 CSS/DOM，不是 Cocos 动画系统。

### 7.3 数值与验收

- **情绪层**：为解决 S0≤100 与 40–90 步的冲突而新增；见 5.1。
- **FR-LV-10 的 R**：展示版步数按教学关节奏手工设定，`R_BY_CHAPTER` 作为设计基准保留；没有用“平均步数 × R”反算预算。模拟记录用于验证可达性。
- **AC-03 通关率**：三关是教学关，模拟通关率 100%，高于需求中“喘息关 85–95%”的目标；完整 75 关的难度曲线仍需内容阶段按真人 playtest 调参。
- **AC-10 道具使用率 / AC-11 分数可达性 / AC-18 帧率与内存**：未做真实玩家与真机基准；当前只有机械模拟、Chromium 浏览器验收与静态资源检查。
- **NFR-05 真机兼容**：只在 Playwright Chromium 上验证；iOS Safari / Android Chrome 真机未测。
- **NFR-08 触控热区**：390px 宽棋盘格 45.5px；360px 宽为 41.75px，略低于 44px 目标；更窄设备需要进一步压缩边距。
- **分享 ≤1 秒**：Canvas 生成在本机远低于 1 秒，但没有做低端机基准。
- **AC-08 / KC 系列埋点**：展示版不采集任何数据，相关假设仍需原型阶段验证。
